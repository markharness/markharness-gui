# 0016: 要素の削除は、何が一緒に消えるかを書いた確認のあとに行う

## ステータス

Accepted(2026-10-09決定)。

## 背景

コアの `knowledge remove` は、要素を物理的に削除する。元に戻せない。種類によって、一緒に消えるものが違う。

- Featureを消すと、配下のBehaviorとScenarioも消える。
- Behaviorを消すと、配下のScenarioも消える。
- 要求を消しても、紐づくFeatureは消えず、紐づきだけが外れる(コアの応答の `detached`)。

## 決定

- 要求(native)・Feature・Behavior・Scenarioのカードに、「〇〇を削除」のボタンを置く。external要求の削除は、提供しない。
- 押すと、確認のモーダルを開く。種類ごとに、何が一緒に消えるかを文で書き、「この操作は元に戻せません。」を添える。件数は、GUIが数えない。
  - 要求: 紐づくFeatureは削除されず、紐づきだけが外れる。
  - Feature: 配下のBehaviorとScenarioも削除される。
  - Behavior: 配下のScenarioも削除される。
  - Scenario: そのScenarioが削除される。
- 削除は、`knowledge remove <種類> <uid>` で行い、成功したら `generate` を呼ぶ。失敗は、コアの文面を、そのまま示す。モーダルは開いたままにする。
- 削除のあとは、選択を要求の表示に戻す。要求自体を削除したときは、何も選んでいない状態にする。

## 代替案

- **確認なしで、すぐ削除する**: 採用しなかった。確認のモーダルを挟む。
- **確認に、消える要素の件数を示す**: 採用しなかった。文だけで知らせる。
- **要求を削除するとき、紐づくFeatureも一緒に削除する**: 採用しなかった。コアの動作に合わせ、Featureを残す。

## 影響

- 要求の削除で生じた、紐づかないFeatureは、[0015](./0015-create-elements-below-their-parent-cards.md) の方法で付け直す。
