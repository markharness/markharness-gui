# 0015: 要素は、親のカードの下から作り、作った要素を選んだ状態にする

## ステータス

Accepted(2026-10-09決定)。

## 背景

詳細ペインは、一覧で選んだケースを起点に、要求 → Feature → Behavior → ケースの順に、カードを積む。新しい要素を、この並びのどこから作るかを決める必要がある。

また、作ったばかりのFeatureやBehaviorには、ケースがない。ケースを起点にしたカードの列には、ケースのない要素が出ないため、作った要素を開く経路が必要になる。一覧が使う `coverage` の「ケースがない機能」は、コミット済みの内容から作るため、作業ツリーで作ったばかりの要素は載らない。

要求に紐づかないFeatureは、コアでは正当な状態だが、一覧は要求を起点に作るため、一覧には出ない。

## 決定

- 作成の入口は、親のカードの下に置く。
  - 一覧の上に「＋ 要求を追加」。
  - 要求のカードの下に「↓ Featureを追加」(開いている要求を、新しいFeatureの `contributes_to` に入れる)。
  - Featureのカードの下に「↓ Behaviorを追加」。
  - Behaviorのカードの下に「↓ Scenarioを追加」。
- 作成は、`uid` なしの `knowledge reconcile` で行い、コアが与えた `uid` を、`reconcile` の応答から受け取る。成功したら `generate` を呼ぶ。
- 作成の直後は、作った要素を選んだ状態にする。Scenarioを作ったときは、コアが生成したケースを選ぶ。
- ケースのない要素へは、作業ツリーの `traceability` の関係から作る一覧で行く。要求の詳細の「この要求のFeature」と、Featureの詳細の「このFeatureのBehavior」に、ケースの有無によらず、すべてを並べ、押すと開く。
- 要求に紐づかないFeatureは、画面の上に、件数と名前を知らせる。GUIから作るFeatureは、必ず要求に紐づく。
- 要求を作るとき、紐づかないFeatureがあれば、「紐づかないFeature」のチェックボックスの一覧を出す。初期状態は、何も選ばない状態とする。選んだFeatureは、新しい要求と同じ1つのIntentで送る(新しい要求に保存されない `key` を付け、Featureの `contributes_to` で、その `key` を指す)。要求の作成と付け替えは、1回の `reconcile` で反映される。
  - 一覧に出すのは、Feature自身にも、そのScenarioにも要求への関連がない、Featureだけである。コアの `contributes_to` は全置換のため、すでに別の要求に紐づくFeatureを出すと、その関連が失われる。
  - すでにある別の要求への付け替えは、提供しない。

## 代替案

- **作成の入口を、1か所の「新規作成」ボタンにまとめ、種類を選ばせる**: 採用しなかった。親が決まった状態で作れるよう、親のカードの下に置く。
- **ケースのない要素への経路に、`coverage` の「ケースがない機能」を使う**: 採用しなかった。作業ツリーの `traceability` の関係から作る一覧を使う。
- **Feature・Behavior・Scenarioを、1つのフォームでまとめて作る**: 採用しなかった。1種類ずつ作る。
- **紐づかないFeatureを、一覧に出す**: 採用しなかった。通知で存在を知らせ、新しい要求の作成で、引き取らせる。
- **要求の作成のとき、紐づき済みのFeatureも選べるようにする**: 採用しなかった。紐づかないFeatureだけを出す。

## 影響

- 要求を削除すると、紐づくFeatureが紐づかない状態になる([0016](./0016-confirm-before-removing-an-element.md))。新しい要求の作成で、それらを付け直せる。
- 画面を開いたあとに、外から別の要求に紐づいたFeatureが、候補に残る場合は、[0018](./0018-values-are-sent-without-checking-outside-changes.md) に従う。
