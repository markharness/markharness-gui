# 0014: 要素の作成と編集は、同じ項目の1つのフォームを、モーダルで開いて行う

## ステータス

Accepted(2026-10-09決定)。

## 背景

GUIで、要求(native)・Feature・Behavior・Scenarioを、作成し、編集する。同じ要素について、作るときと直すときで、入力する場所や、保存の単位が違うと、利用者は「どこで何を直すのか」を覚え直すことになる。

コアには、次の制約がある。

- Scenarioは、作成時に、説明と、1件以上のフェーズ(手順と期待結果)が必須である。Behaviorは、作成時に説明が必須である。
- `procedures`(Behaviorの共通手順)と `phases`(Scenarioの手順と期待結果)は、記述すると全体が置き換わる。
- 空の文字列は、省略とは区別して拒否される。

## 決定

- 要求・Feature・Behavior・Scenarioの編集と作成のフォームは、モーダル(`<dialog>`)で開く。Escキーで閉じる。背景のクリックでは閉じない(入力中の内容を、誤って失わないため)。閉じた時点で、入力は捨てる。
- 作成と編集は、同じ項目の、同じ部品を使う。違うのは、初期値(作成は空)と、送り先(作成は `uid` なしの `reconcile`、編集は `uid` を指定した `reconcile`)だけである。
  - 要求・Feature・Behavior: ID・ラベル・分類。要求とBehaviorは、説明も持つ。
  - Behavior: 共通手順の行も、このフォームに入れる。
  - Scenario: ID・ラベル・説明・実装メモと、フェーズの行を、1つのフォームに入れる。
- 保存は1回で、フォームのすべての項目を送る。「項目は保存したが、手順は保存していない」という状態を作らない。
- 1行の入力欄でEnterを押しても、何も起きない(保存も、行の追加もしない)。
- 拒否された保存は、コアの診断を、そのまま表示する。GUIは、入力の検証を持たない。コアが拒否する値(空の説明、空の手順など)は、そのまま送る。
- 送る値は、次の3つの場合だけ、省く。いずれも、コアが空の値を拒否する、または、空を送ることに意味がないためである。
  - 作成で、説明が空のときの、説明(要求)。
  - もともと実装メモがなく、空のままの、Scenarioの実装メモ。
  - もともと共通手順がなく、何も足していないときの、Behaviorの共通手順。

## 代替案

- **項目と、手順・共通手順を、別のボタン・別の保存にする**: 採用しなかった。1つのフォームで、1回で保存する。
- **編集を画面の中でその場に開く**: 採用しなかった。モーダルで開く。
- **背景のクリックでも閉じる**: 採用しなかった。キャンセルと、Escキーで閉じる。
- **空の値をGUIで取り除いてから送る**: 採用しなかった。上の3つを除き、フォームの値をそのまま送り、コアの診断を示す。

## 影響

- Scenarioの「手順を編集」と、Behaviorの「共通手順を編集」の、別のボタンはない。
- 保存のたびに、フェーズや共通手順は、まるごと送られる(コアが全体を置き換えるため)。内容が変わらなければ、コアは「変更なし」と扱う。
