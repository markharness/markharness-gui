# 0005: GUIは、refの候補を出すために、読み取り専用のgitを呼ぶ

## ステータス

Accepted(2026-10-04決定。2026-10-06に、候補の範囲と、`git` が使えないときの扱いを改めた。理由は [0012](0012-compare-with-a-tag.md))。

## 背景

Change Impactは、比べる2つのコミット(`--base`、`--head`)を、Release Coverageは、読むコミット(`--at`)と、リリース名を、gitのrefで受け取る。利用者には非開発者が含まれ、`v1.0` や `HEAD~3` のようなrefの文法を、打たせるのは現実的ではない。

`markharness` には、refやリリース名の一覧を返す読み取りが無い。引き継ぎ文書は、GUIがmarkharnessのJSON出力だけを読むとしている(StrictDocのエクスポートを除く)。この約束の目的は、`.markharness/` 配下の内部ファイルの形式が、予告なく変わっても、GUIが影響を受けないようにすることである。refはGitの概念で、markharnessの知識の一部ではないので、本体に一覧の読み取りを依頼しない。

markharnessは、タグを基準に、変更と影響を確認する。このため、候補は、タグから始める。ブランチと最近のコミットは、実際の利用で必要と確認されるまで、実装しない。`git` が使えないのは、`git` が `PATH` に無い、または実行が失敗したときだけで、markharness自体がgitのリポジトリを前提にするため、まれである。まれな場合のために、自由入力の画面は作らない。

## 決定

GUIは、refの候補を出すためだけに、読み取り専用の `git` を呼んでよい。

- 呼んでよいのは、`git for-each-ref`(タグとブランチ)と、`git log`(最近のコミット)だけである。書き込みを伴う `git` は、呼ばない。
- 実装する候補は、タグ(`git for-each-ref refs/tags`)だけで、新しいタグを先に出す。ブランチと最近のコミットは、実際の利用で必要と確認されたときに足す。
- 候補は、`markharness` に渡す値の入力を助けるだけである。画面の内容は、これまでどおり、markharnessのJSON出力だけから作る。
- 候補は、タグを、リリース名の候補にも使う(本体は、リリース名に、Gitのタグ名が自然、としている)。選んだ名前に選定の記録が無いときは、記録が無いことを画面に示す。
- `git` が見つからない、または失敗したときは、候補を出さない。自由入力には切り替えない。エラー画面にはしない。

## 代替案

- **自由入力だけにする**: 採用しなかった。候補をドロップダウンで選ぶ。
- **`markharness` に、refの一覧を返す読み取りを依頼し、それまで自由入力にする**: 採用しなかった。読み取り専用の `git` で、候補を出す。
- **`git` が使えないときに、自由入力に切り替える**: 採用しなかった。候補を出さない。

## 影響

- 引き継ぎ文書の「GUI側で決めてよいこと」と、AGENTS.mdの「markharnessとの境界」に、この例外を書いた。
- Windowsでは、`git` が `git.exe` で、`PATH` から見つかる。
- 候補を出すために、`git` を子プロセスとして、非同期に呼ぶ実装と、その出力を読む検証が、GUI側に加わる。
- `git` が使えないとき、比較元を選べないので、比較は使えない。
