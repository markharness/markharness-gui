# 0020: 比較対象に「未コミットの編集」を加え、`impact --worktree` で `HEAD` と作業ツリーを比べる

## ステータス

Accepted(2026-10-13決定)。[0012](0012-compare-with-a-tag.md) の、比較の対象がタグだけであること、注記が常に「コミット済みの内容で比較」であること、`git` が使えないと比較が使えないことを改める。[0005](0005-readonly-git-for-ref-candidates.md) の「`git` が使えないときの扱い」のうち、比較が使えないとする部分も改める。

## 背景

利用者は、コミットする前に、編集がどの要求とケースに影響するかを、画面で知りたい。

markharnessは、`impact --worktree` を足した(0.7.1と0.7.2)。`HEAD` と作業ツリーの比較を返す。基準は `HEAD` に固定で、タグから作業ツリーへの比較はできない。未追跡のファイルも含む。出力の `record_kind` は `change_impact_worktree` で、フィールドの構成は `change_impact` と同じである。範囲の中にコミットがないため、確認の記録(`Spec-Reviewed`)は数えられず、ケースの `status` は `followed_up` と `unconfirmed` のどちらかで、`confirmed` は出ない。

タグ比較と、未コミットの比較は、別の問いに答える。タグ比較は、リリースからの変更のうち、確認し直すケースの数を示す。未コミットの比較は、いまコミットしたら影響が出るケースの数を示す。

タグ比較は、コミット済みの内容だけを読むので、GUIでの編集の影響を受けない。未コミットの比較は、作業ツリーを読むので、GUIでの編集のたびに結果が変わる。

`impact --worktree` は、一時的なインデックスで `git add -A` と同じ処理をするため、編集中のファイルの内容が、オブジェクトとして書き込まれる。HEADと同じ内容のファイルは、同一のオブジェクトで、増えない。増えるのは、編集中のファイルの分だけで、1回あたり数十KBから数百KBである。同じ内容を何度読んでも、増えない。`git gc` を先に実行しても、この書き込みは防げない。参照されないオブジェクトは、Gitが自動で整理する。大きな未追跡のファイル(`.gitignore` に入れていない動画やビルド成果物)は、実行のたびにハッシュの計算と書き込みを起こすが、これは `.gitignore` で防ぐ。

## 決定

- 比較の選択のラベルを「比較元」から「比較対象」に改める。プルダウンの選択肢は、「未選択」「未コミットの編集」、タグの順にする。ブランチと最近のコミットは、0012のとおり、足さない。
- 選択の直下に、比べている範囲を示す。「未コミットの編集」では「HEAD → 作業ツリー」、タグでは「<タグ> → HEAD」とする。「未選択」のときは、範囲も、注記も示さない。
- 注記は、選択に応じて切り替える。タグでは「コミット済みの内容で比較」、「未コミットの編集」では「未コミットの変更に基づく暫定的な影響分析(未追跡のファイルを含む)」とする。
- 「未コミットの編集」は、`impact --worktree` を呼ぶ。呼び出しごとに、受け付ける `record_kind` を1つに決める。「未コミットの編集」は `change_impact_worktree`、タグは `change_impact` だけを受け付け、もう一方が返ったら、対応しない種類として止まる。両方を受け付けると、暫定の結果を、確定した結果として取り込む誤りを防げない。
- 件数は、0012と同じ規則で数える。`status` が `confirmed` でないケースを、`case_uid` で重複を除いて数える。ケースの題名の色づけも、同じ色(`--to-confirm`)である。件数の名前は、タグでは「変更後に確認対象となるケース」、「未コミットの編集」では「影響を受けるケース」とする。「未コミットの編集」には `confirmed` が出ないので、前者の名前は合わない。
- `git` が使えず、タグを取れないときも、「未コミットの編集」は選べる。GUIは、この比較に `git` を呼ばない。比較に失敗したときは、本体のメッセージを、件数の位置に、そのまま示す。
- GUI自身の編集のあと、「未コミットの編集」を選んでいるときだけ、比較を読み直す。編集が作業ツリーを書き換え、結果が変わるためである。タグを選んでいるときは、0012のとおり、読み直さない。
- 読み直すのは、利用者の再読み込みと、GUIの編集の保存後だけに限る。ファイル監視と、定期的な再取得はしない。
- 選んだ比較は、保存しない。
- GUIは `git gc` を呼ばない。書き込みを伴う `git` を呼ばない方針による。増えるオブジェクトの量は、背景のとおり、小さい。

## 代替案

- **比較元と比較先の、2つのボックスにする**: 採用しなかった。ボックスは1つで、そこから比較対象を選ぶ。
- **未コミットの比較を、タグ比較とは別の表示にする**: 採用しなかった。同じ位置の、プルダウンの選択肢にする。
- **件数の名前を、2つの比較で共通にする**: 採用しなかった。選択に応じて切り替える。
- **編集のあと、常に比較を読み直す**: 採用しなかった。「未コミットの編集」を選んでいるときだけ、読み直す。
- **両方の `record_kind` を、どちらの呼び出しでも受け付ける**: 採用しなかった。呼び出しごとに1つに決める。
- **`impact --worktree` の前に、`git gc` を実行する**: 採用しなかった。`git gc` は呼ばない。
- **`git` が使えるときだけ、「未コミットの編集」を選べるようにする**: 採用しなかった。常に選べる。

## 影響

- [0012](0012-compare-with-a-tag.md) の、「コミット済みの内容で比較」の注記と、`git` が使えないときに比較が使えない記述は、この決定に従う。0012のその他の決定は、変わらない。
- `.github/markharness-rev` を、`impact --worktree` を含む、本体のコミット(`598bde6`)に更新した。
- 「未コミットの編集」では、ケースが紐づかない要求(`cases` が空)は、0012と同じく、件数にも画面にも現れない。
- 作業ツリーを読むので、編集の途中の、整合の取れていない状態を読んで、失敗することがある。その場合も、本体のメッセージを、そのまま示す。
