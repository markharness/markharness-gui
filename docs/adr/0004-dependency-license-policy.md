# 0004: 依存は、MITとして提供でき、配布時の義務を確実に履行できる範囲に限る

## ステータス

Accepted(2026-10-03決定)。第三者ライセンスの表示を生成・検証する仕組みは、まだ無い。最初のリリースの前に整える。

## 背景

markharness-guiは、markharnessの配布物に同梱される。これまでの依存の規約は、markharness本体の許可リストを出発点にして、コピーレフトを、推移的な依存でも、一律に許さないとしていた。本体の許可リストの背景は、GPL-3.0の依存が、静的リンクで1つのバイナリになり、宣言したMITと矛盾した事故である。事故の対象はGPL-3.0で、MPL-2.0のような弱いコピーレフトは、検討されていない。

実行形態をTauri 2とする([0001](0001-runtime-shell-tauri.md))と、`cargo deny` で、許可リストの外のライセンスが見つかった(2026-10-03、WindowsとmacOSのどちらの対象でも)。

- MPL-2.0: `cssparser`、`cssparser-macros`、`selectors`、`dtoa-short`(いずれも、Tauriの中核の `tauri-utils` が使う `dom_query` 経由)と、`option-ext`(`dirs` 経由)。Tauriを使わず `wry` だけにしても、macOSでは `option-ext` が残る。
- BSD-3-Clause: `brotli`、`alloc-no-stdlib`、`alloc-stdlib`、`matchit`(`matchit` は、MIT AND BSD-3-Clause)。

規約の文言は、事故の理由(GPL-3.0)より広い。そこで、依存を限る基準を、ライセンスの分類(コピーレフトか否か)ではなく、検証できる2つの条件にする。

## 決定

依存は、次の2つを満たすものに限る。

1. **markharnessをMITとして提供できる。** 依存のライセンスが、全体への条件を課さずに、MITの配布物へ組み込める。
2. **配布時に生じる義務を、プロジェクトが機械的に、確実に履行できる。** 義務が列挙でき、リリースの自動の手順で果たされ、CIで検証される。利用者の操作や、依存ごとの人の判断に、頼らない。

この基準で、ライセンスを次のように扱う。

| ライセンス | 扱い | 理由 |
|---|---|---|
| MIT、MIT-0、Apache-2.0、Apache-2.0 WITH LLVM-exception、BSD-2-Clause、BSD-3-Clause、BSL-1.0、Unicode-3.0、Unlicense、Zlib | 許可 | 義務は、ライセンス表示の同梱で、自動で生成できる |
| MPL-2.0 | 改変しない場合に限り許可 | 義務は、ライセンス表示と、ソースの入手先(crates.io)の同梱で、自動で生成できる。改変すると、義務が増え、機械的な履行が難しくなる |
| LGPL | 許可しない | 静的にリンクするRustのバイナリでは、利用者による差し替えの保証が、確実にできない |
| GPL、AGPL、SSPL | 許可しない | MITとして提供できない |
| 独自のライセンス、OSIの承認がないもの、ライセンスの記載がないもの | 許可しない | 義務を列挙できない |

利用者への約束は、「copyleft-freeな依存の木」ではなく、「配布物に含まれるすべての依存のライセンスと、表示を同梱している」ことである。

### 履行の仕組み(最初のリリースの前に必須)

- 第三者ライセンスの表示のファイルを、配布物に含まれる依存(Rustと、npmの本番の依存)の一覧から、ビルドで生成し、配布物に同梱する。MPL-2.0のクレートは、名前、版、ソースの入手先を載せる。
- 生成されたファイルが、古い、または欠けているとき、CIを失敗させる。
- 許可リストの外のライセンスは、CIが止める(`cargo deny check licenses`)。
- 依存の改変を防ぐため、依存の差し替え(`[patch]`、gitやpathの依存)を、CIが止める。
- 許可リストに新しいライセンスを加えるときは、上の2つの条件に対する検証の結果を、ADRに書く。

## 代替案

- **copyleft-freeを保証する(MPL-2.0も許さない)**: 実行形態が、ブラウザ方式(Rustの小型サーバー)に戻る。WindowsとmacOS(arm64)のどちらでも、BSD-3-Clauseの許可だけで通ることを確認した。ただし、終了の検出と、ローカルのポートの防御が、恒常的な保守になる([0001](0001-runtime-shell-tauri.md))。保証したい相手と目的が、現時点では、無い。
- **強いコピーレフトだけを避け、MPL-2.0は、推移的な依存に限る**: 直接の依存でも、推移的な依存でも、MPL-2.0の義務は同じで、「推移的に限る」条件に根拠が無い。
- **Tauriを使わず、`wry` と `tao` だけを使う**: macOSで、MPL-2.0の `option-ext` が残るため、解決にならない。
- **MPL-2.0のクレートを、自前の実装に置き換える**: `tauri-utils` の中核の依存で、置き換えは、Tauriの改変になる。

## 影響

- Windowsの実行ファイルが使うWebView2や、macOSのWKWebViewは、OSが提供する実行環境で、依存ではない。この基準の対象外とする。WebView2のインストーラーを、配布物に同梱することにした場合は、その利用条件を、改めて判断する。
- 開発・テストのビルドだけで使う依存は、配布物に含まれない。従来の規約は、これも許さないとしている。この決定では、その部分は変えない。
- markharness本体のGUI入りアーカイブには、GUIの第三者ライセンス表示のファイルを同梱するよう、本体へ依頼した。本体自身のアーカイブも、第三者ライセンスの表示を含んでいないため、同じ基準を満たすよう、本体へ依頼した。
