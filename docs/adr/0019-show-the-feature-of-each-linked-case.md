# 0019: 要求に紐づくケースの一覧は、Featureでまとめて、Feature名を見出しにする

## ステータス

Accepted(2026-10-12決定)。

## 背景

要求に紐づくケースの一覧は、2か所にある。要求テーブルの「紐づくケース」列と、詳細ペインの「紐づくケース」である。どちらも、ケースがどのFeatureに属するかを、一覧の見た目から確認しにくかった。

- 要求テーブルは、ケースのタイトルだけを並べ、Featureを示さなかった。
- 詳細ペインは、各ケースに「Feature › Behavior」の1つの文字列を添えたが、Featureごとのまとまりがなかった。
- ケースの並びは、コアが返す要求の `case_uids` の順で、同じFeatureのケースが隣り合う保証がない。

要求は、複数のFeatureが貢献して満たす。読み手が一覧から知りたいのは、「この要求を、どのFeatureが、どのケースで確かめているか」である。そのため、ケースだけでなく、ケースが属するFeatureが、一覧の見た目でわかる必要がある。

この情報はすべて、`traceability` のJSON出力にすでにある。コアへの依頼は要らない。

## 決定

- 要求に紐づくケースは、Featureでまとめて並べ、各まとまりの先頭に、Feature名を見出しとして出す。要求テーブルの列と詳細ペインの両方で、同じ規則を使う。
- まとまりの並びは、Featureが `case_uids` の中に初めて現れる順とする。同じFeatureの中の並びは、`case_uids` の順のままとする。
- FeatureをたどれないケースはFeature名を持たない。見出しのないまとまりとして、最後に置く。「不明」などの文言は出さない。
- 詳細ペインの各ケースの補足は、Behavior名だけにする。Feature名は見出しに出るため、ケースごとに繰り返さない。
- まとまりの判定は、Feature名ではなく、Featureの `uid` で行う。同じ名前の別のFeatureを、1つにまとめないためである。
- クリックや展開・折りたたみなどの操作は足さない。ケースの選択と詳細の表示は、変えない。
- まとめる規則は、`rows.ts` の `groupByFeature` に置き、両方の画面が使う。

## 代替案

- **並びを変えず、各ケースにFeature名を添える**: 採用しなかった。同じFeatureのケースが離れるため、まとまりが見えない。代わりに、Featureでまとめて見出しにした。
- **「Feature › Behavior」の1つの文字列を、そのまま残す**: 採用しなかった。Featureごとのまとまりが作れない。代わりに、FeatureとBehaviorを別の値にした。
- **FeatureをたどれないケースをFeature不明の見出しでまとめる**: 採用しなかった。ユーザーが直すべき状態に見える。代わりに、見出しなしのまとまりにした。
- **Featureのまとまりを、折りたためるようにする**: 採用しなかった。操作を足さずに、見た目だけで確認できるようにした。
