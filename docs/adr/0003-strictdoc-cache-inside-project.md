# 0003: StrictDocキャッシュは、プロジェクトの中の `.markharness-gui/` に置く

## ステータス

Accepted(2026-10-03決定)。ただし、`.gitignore` への追加を本体の `markharness init` が行うまでは、キャッシュが未追跡のファイルとして現れる。

## 背景

`source: external` のRequirementの見出しと階層を得るには、GUIが `strictdoc export --formats=json` を実行する。プロジェクトによっては、1回に20秒かかるため、結果をStrictDocキャッシュとして保存し、StrictDocの文書か設定が更新されたときだけ、裏で再エクスポートする。

保存場所は、引き継ぎ文書では、プロジェクトの中にファイルを増やさない場所(OSのキャッシュ領域など)が、勧められていた。

## 決定

StrictDocキャッシュは、プロジェクトのルートの `.markharness-gui/` に置く。`.markharness/` の中には置かない(GUIは、StrictDocのエクスポートを除いて、`.markharness/` を直接読み書きしないため)。

このディレクトリを、Gitの作業ツリーに現れないようにする設定は、markharness本体の `markharness init` が、`.gitignore` に追加して行う。GUIは、`.gitignore` も `.git/info/exclude` も書かない。この追加を、GUIをmarkharnessの配布物に同梱するための受け入れ条件として、本体へ依頼した。

## 代替案

- **OSのキャッシュ領域に、プロジェクトのルートのパスのハッシュをキーにして置く**: プロジェクトの中に、ファイルが増えない。ただし、プロジェクトを移動・複製すると、キャッシュのキーが変わり、再エクスポートが走る。プロジェクトに紐づいたキャッシュを、プロジェクトと一緒に持ち運べる点を優先して、採らなかった。
- **GUIが、プロジェクトの `.gitignore` に追記する**: 利用者がコミットしているファイルを、GUIが黙って書き換えるため、採らなかった。
- **GUIが、`.git/info/exclude` に追記する**: 利用者の差分には現れないが、GUIが、リポジトリのGitの内部に書くことになる。また、Gitのworktreeなど、`.git` がファイルの場合の扱いが、必要になるため、採らなかった。

## 影響

- 本体が対応するまで、開発中は、`.markharness-gui/` を、手で `.gitignore` に追加する。
- 既に初期化済みのプロジェクトでは、`markharness init` の再実行で、追記されるかどうかが、本体の判断に委ねられている。追記されない場合は、本体の `markharness gui`(起動の役)が、起動時に追記する案が、本体への依頼に書かれている。
- キャッシュを、利用者が必ず捨てられる操作(強制再エクスポート)を、画面に用意する。古い内容を見せ続けないための、必須の制約である。
