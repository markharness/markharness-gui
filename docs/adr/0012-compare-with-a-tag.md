# 0012: 比較元のタグと `HEAD` を `impact` で比べ、確認対象となるケースの件数を示す

## ステータス

Accepted(2026-10-06決定)。[0009](0009-fact-provenance-and-human-attention.md) の「後で決めること」のうち、「読んだ文脈(コミット、リリース、比較範囲)の扱い」の、比較範囲を決める。[0005](0005-readonly-git-for-ref-candidates.md) の「候補の範囲」と「`git` が使えないときの扱い」を改める。

## 背景

利用者が、あるタグ(たとえば直近のリリース)から `HEAD` までの間に、どれだけのテストケースを、確認し直す必要があるかを、画面で知りたい。

markharnessは、`impact --base <rev> --head <rev>` で、2つのリビジョンの間に触れられた要求と、それに紐づくケースが、確認済みかどうかを返す。ケースは、次の状態のどれかを持つ。

- `confirmed`: 要求とケースの組に、有効な確認の記録(`Spec-Reviewed`)がある。
- `followed_up`: 範囲の中で、要求とケースの両方が変わったが、確認の記録がない。
- `unconfirmed`: 要求が変わったが、ケースが変わらず、確認の記録もない。

markharnessは、タグを基準に、変更と影響を確認する。`impact` は、コミット済みの内容だけを読み、未コミットの編集を反映しない。`--base` は、本体が推論しない。

## 決定

- 画面は、比較元のタグを、利用者に選ばせ、選んだ文字列を、そのまま `impact --base=<タグ> --head HEAD` に渡す。GUIは、refの存在や祖先関係を確かめない。`impact` が失敗したら、本体のエラーメッセージを、件数の位置に、そのまま示す(0件とは区別する)。
- 比較元の候補は、タグだけとする。読み取り専用の `git for-each-ref refs/tags` で取り、新しいタグを先に出す。ブランチと最近のコミットは、実際の利用で必要と確認されたときに足す。
- 「変更後に確認対象となるケース」は、`impact` の `requirements[].cases[]` のうち、`status` が `confirmed` でないものを、`case_uid` で重複を除いて数えた件数とする。`followed_up` を含む。GUIは、これ以上の推論をしない。0件は「0件」と示す。
- 比較元は、初めは「未選択」とし、件数は示さない。GUIは、タグを自動では選ばない。選んだタグは、保存しない。
- `git` が使えず、候補を取れないときは、候補を出さない(自由入力には切り替えない)。このとき、比較元を選べないので、比較は使えない。
- 画面に、「コミット済みの内容で比較」と、注記する。作業ツリーの未コミットの編集は、件数に反映されない。
- 本サマリーは既存Caseのうち再確認対象となる件数のみを示す。impact対象RequirementにCaseが存在しない状態については、本サマリーでは扱わない。その状態をどう提示するかは未決定とする。
- サマリーは、既存のContextBarに置く。件数をクリックしても、何も起きない。一覧や詳細は、示さない。

## 代替案

- **ブランチと最近のコミットも、比較元の候補にする**: 採用しなかった。比較元の候補は、タグだけにする。
- **比較元を、自由入力にする**: 採用しなかった。タグをドロップダウンで選ぶ。
- **`git` が使えないとき、自由入力に切り替える**: 採用しなかった。候補を出さない。
- **直近のタグを、比較元の初期値にする**: 採用しなかった。初めは「未選択」にする。
- **`unconfirmed` だけを、確認対象として数える**: 採用しなかった。`confirmed` でないものを、すべて数える。
- **要求とケースの組の件数を数える**: 採用しなかった。ケースを、`case_uid` で重複を除いて数える。
- **件数が0件のときと失敗したときを、同じ表示にする**: 採用しなかった。失敗は、本体のメッセージを示し、件数は示さない。
- **作業ツリーの未コミットの編集も含めて比べる**: 採用しなかった。`impact` が読むコミット済みの内容で比べる。

## 影響

- ケースが紐づかない要求(`cases` が空)は、件数にも画面にも現れない。その提示は、未決定のままである。
- 1つの要求に複数のケースが紐づき、状態が混ざる出力と、`stale_pins` の中身は、実物で確かめていない。件数の導出は、`stale_pins` と `rejected_trailers` を使わない。
- 比較元のタグが、`HEAD` の祖先でないなど、`impact` が失敗する場合の挙動は、本体のメッセージに従う。
- 再読み込みで、タグの候補と、選択中の比較を、読み直す。
