# 0009: 表示する情報は、出所を区別して示す

## ステータス

Accepted(2026-10-06。原則は、利用者が定めた。第1版は、最小の範囲に絞る)。

## 背景

画面に出す情報には、出所の違うものが混ざる。本体(markharness)の出力、連携元(StrictDoc)の情報、GUIが結んだり、まとめたりしたものがある。本体は、StrictDocの親子関係を知らないので、本体の事実と、GUIが親子の上で作った集計を、1つの行に区別なく並べると、矛盾に見える表示になる。

## 用語

- **Atomic Fact**: 出所が1つで、対象が1つの、それ以上分けない事実(本体の出力の項目、StrictDocの要求の本文など)。
- **Aggregate**: 配下のAtomic Factを、親でまとめたもの。
- **Derived Evidence**: 複数のFact、出所、関係から導いた情報。

## 原則

1. Atomic Factには一意の出所があり、対象と出所を追跡できること。
2. Atomic Factは、それが語る対象自身にのみ付与する。親への意味的な伝播はしない。
3. 配下のAtomic Factを親で表示するときはAggregateとして扱い、「親自身のFact」と混同しない。
4. 複数のFact・Source・Relationから導出した情報はDerived Evidenceとして扱い、何から導出したか説明可能にする。
5. デフォルト画面ではEvidenceの完全性より、人間が「どこを見るべきか」を短時間で判断できることを優先する。完全なFact/Relation/Sourceはdrill-downで確認できること。

## 第1版の範囲

- 判定として扱うのは、**テストが紐づいているか、紐づいていないか**だけとする。要求の `cases` が空であれば、紐づいていない。ケース数が0であることで読めるので、判定の専用の表示は設けない。`feature_has_no_case` などは、理由として添える事実であり、判定ではない。
- 情報は、**事実として表示するだけ**とする。強調や、優先づけ(Attention)は、行わない。
- 文脈(コミット、リリース、比較範囲)は、原則に加えない。
- 件数(ケース数、内訳)と、親子による集計の扱いは、いまは決めない。

## 後で決めること

第1版の画面([0008](0008-requirement-rows-and-detail-pane.md))を使った結果から、必要になった時点で、あらためて決める。

- 人間の注意を、どこに向けるか(強調、並べ替え、折り畳み、親を入口にすること)と、その規則。
- 件数と、親子による集計の扱い(本体の出力と、GUIが作るものの境界)。
- 読んだ文脈(コミット、リリース、比較範囲)の扱い。
