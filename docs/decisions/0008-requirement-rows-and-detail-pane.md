# 0008: 表示は、要求ごとの行と詳細ペインを、3つの視点で共有する

## ステータス

Accepted(2026-10-05決定)。要求の行の列と、ケースの見せ方の細部、StrictDocとの連携、詳細ペインに出す内容は、別に決める。

## 背景

本体の読み取り出力(`traceability`、`coverage`、`impact`)は、どれも、要求を根にした「要求 → Feature → ケース」の構造を持つ。関係、Release Coverage、Change Impactを、別々の画面にすると、同じ構造を、画面ごとに作ることになる。

先行モックアップ(別リポジトリ `markharness-viewer`)は、作業ツリーの現在の状態だけを、StrictDoc要求の木と、要求に紐づかないFeatureの木の2本で示し、追加・編集の操作を、すべてのタイルに並べていた。一方で、要求のレーンと、ケースのレーンを、横に並べる形は、要求とケースを見比べるのに向いていた。

Release Coverageで、人間が判断する単位は、要求である。「この要求は、十分にテストされているか」を、要求の文と、そのケースの題名を、並べて読んで判断する。ケースの数は、見る場所の手がかりであり、件数だけで、充足や合否を断定しない。そのため、判断に要るもの(要求の文、ケースの題名、状態)は、要求の行に出ているべきである。

Feature → Behavior → Scenarioと段を下げる木は、人間の注意を、階層をたどることに使わせ、要求とケースの比較に向かない。

## 決定

- 画面は、上部の文脈バー(読むコミット、リリース、比べる範囲)、左の要求の一覧、右の詳細ペインで構成する。
- 「関係」「Release Coverage」「Change Impact」は、別の画面ではなく、同じ要求の一覧と詳細ペインを共有する**視点**とする。視点を切り替えると、先頭の要約と「注意が要るもの」、行に出す情報が変わる。
- 一覧は、**1行が1つの要求**とする。StrictDocの文書と節のまとまりは、元の文書と見比べられるように残す。要求の下に、ケースを段を下げて並べない。
- 要求の行に、要求の題名と本文、ケース数、状態の内訳を出す。ケースの題名と状態は、要求の行の右側に、並べて出す。ケースが多いときは、件数で省略し、状態に注意が要るものを先に出す。
- Feature・Behaviorは、行に出さない。詳細ペインの「関連チェーン」(要求 → Feature → Behavior → Scenario → TestCase)に出す。ケースのない機能は、その要求の行に、「ケースなし」と示す。
- 要求への紐づけが、Feature単位でも、Scenario単位でも、表示は変わらない。どちらでも、その要求を検証するケースが、要求の行に並ぶ。
- 操作(将来の編集を含む)は、選んだ要素の詳細ペインに置く。
- 要素の同一性は、`*_uid` で判断する。
- 件数や状態の判定は、本体の出力に従い、GUIは、計算し直さない。要求の親子(StrictDoc)をまたぐ集計は、本体が持たない情報なので、GUIが、StrictDocの親子から行う。
- Change Impactの行を、同じ形にするかは、Release Coverageの形が決まってから決める。

## 代替案

- **視点ごとに、別の画面にする**: 部品が3組になり、後から編集を加えるときの置き場も、3か所になる。
- **先行モックアップのように、木を2本にする**: Featureの位置が、紐づきの有無で移り、同じ要素を探しにくい。
- **Feature → Behavior → Scenarioの段を下げた木にする**: 要求の行に判断の材料が出ず、人間の注意が、階層に使われる。
- **要求 → ケースの2段の木にする**: 段は減るが、要求の行が、数字1つになり、要求とケースを左右で読み比べられない。
- **先行モックアップの、要求とケースの対応表(C案)**: 先行モックアップは、「検証方法・実装状態を、セルを選ばずに判別できない」ことを理由に、主表示に採用しなかった。この決定でも、ケースのセルが、情報で詰まると、同じ問題に戻る。実際の画面で、確かめる。

## 影響

- `coverage` と `impact` は、コミット済みの内容だけを読む。画面は、文脈バーで選んだ1つのコミットに固定して、3つの出力を、すべて、同じコミットで読む。作業ツリーの未コミットの内容を、どの視点で見せるかは、編集を設計するときに決める。
- 要求とケースの対応は、本体の出力の紐づき(Feature単位とScenario単位)から作る。親を `uid` で指す出力が要る。
- 詳細ペインに、説明文や手順を出すには、本体の読み取り出力に、その項目が要る。
- 要求の行に、本文を出すには、StrictDocの要求の本文が要る(`traceability` は、external Requirementの本文を持たない)。
